## Weekend load (every Saturday & Sunday — non-negotiable)

Saturdays and Sundays are **heavier than weekdays (~5–6 hrs)**, not lighter:

- **Weekly test days land on Saturdays.** Days 7/14/21/28/35/42 are weekly-review
  tasks but are *scheduled on the following Saturday* (Nov 21, Nov 28, Dec 5,
  Dec 12, Dec 19, Dec 26). The Thursday they were originally dated is now a
  buffer/catch-up day for any overflow from the week.
- Every Sat/Sun adds a **WEEKEND LOAD block** on top of the normal day:
  one timed sectional (Quant/Reasoning/English rotating), one extra puzzle or
  RC set, weekly GA recall (15 facts from the week's log), a descriptive piece
  (essay or precis, alternating), and a redo of the week's error-log entries.
- Sunday = lighter of the two weekend days only in that its test block is a
  sectional rather than a full mock — the total hours stay the same.

## The strict back-revision rule (what makes this plan work)

Reading a subject once = learning it. **Rewriting it weeks later = owning it.** The exam tests what you can produce from memory in 90 seconds — this block builds exactly that.

**Rotation — always revise the subject you FINISHED the week before:**

| Your current week | Back-revision subject (15 min/day) |
|---|---|
| Days 1–7 | — (nothing to revise yet; use the time for extra drills) |
| Days 8–14 | DBMS & SQL — one section/day: keys/closure → NF tree → SQL ops → ACID/isolation → indexing → redo a wrong question |
| Days 15–21 | Networks — OSI table → device map → port table → TCP/UDP → subnetting drill → email trio |
| Days 22–28 | InfoSec — CIA → attack list → crypto table → auth factors → defenses → audit |
| Days 29–35 | OS + DA/Shell/DW — scheduling → deadlock → paging → Python slicing → OLAP ops → shell vars |
| Days 36–42 | DSA + Programming — sorting table → tree formulas → graph formulas → OOP pillars → dry-run a snippet |
| Days 43–49 | Weakest-first from error log + ALL memory tables (the blitz week already is revision) |

**Rules of the block:**
1. **Write before you look.** Blank page → write the table/section from memory → THEN open the notes and mark what you missed. The gap is tomorrow's target.
2. Rotating, not perfectionist — each day hits a different section; over a week the whole subject cycles.
3. If a section produces 2+ gaps two days running → that topic goes into the error log as a weak topic and gets a real re-study session on the next weekly day.

## Score checkpoints — the plan measures itself

Mocks aren't just practice — they're the instrument that tells you if the plan is working. Record every score in `06_Mocks_and_Practice/` (or the dashboard tracker).

| Checkpoint | Test | Target | If below target |
|---|---|---|---|
| **Day 14** | Full Test (Phase I) #1 | Baseline — record it, no target yet | Identify weakest section; that's your Paper-1 rotation focus |
| **Day 21** | Full Test (Phase I) #2 | Combined ≥ +10 over baseline | Swap one IT block → weak-section drilling |
| **Day 28** | Paper 2 IT chapter/subject tests | ≥ 50% raw on IT tests | Next week's lighter topic gets traded for re-study |
| **Day 35** | Full Test (Phase I) #4 | Combined ≥ +20 over baseline; every section above sectional cutoff | Panic-check: a failing section gets 2 of its drills daily, not 1 |
| **Day 42** | Full Phase-1 sim | On track: Paper 1 ≥ 60%, Paper 2 ≥ 55–60% | Blitz week becomes weak-area week — PYQs only on strong topics |

Rule: **below target twice in a row → the plan bends, not breaks.** Trade the next lighter IT topic day for the weak area; never drop mocks to "make time" — the mock IS the measurement.

## Missed-day protocol (strict)

1. **One rule:** a missed day's content folds into the NEXT day's back-revision slot — never carry a full day, never double days.
2. **Weekly mock days NEVER move.** They're pinned to Saturdays — that's why they're on weekends. Everything else bends around them; the Thursday slot is the week's overflow buffer.
3. Miss 2+ days in a row → drop that week's lowest-weightage IT topic section (OS first, then Emerging), keep everything else.
4. A missed day is data, not failure — note WHY in the tracker; if the same cause repeats, it's a schedule problem to fix, not a discipline problem.
